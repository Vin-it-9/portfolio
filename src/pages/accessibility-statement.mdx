This website is the personal portfolio of Vinit Shinde. I want everyone to be able to read about my work, explore my projects, and get in touch, regardless of ability or circumstance. I am continually improving the site and applying relevant accessibility standards.

## Measures to support accessibility

I take the following measures to make this website accessible:

- Build with semantic HTML and a logical heading structure
- Include accessibility considerations in development and code review
- Test keyboard navigation, focus states, and color contrast
- Support light and dark themes, high-contrast mode, and reduced motion
- Welcome and act on accessibility feedback

## Conformance status

The [Web Content Accessibility Guidelines (WCAG)](https://www.w3.org/WAI/standards-guidelines/wcag/) define requirements for designers and developers to improve accessibility for people with disabilities. It defines three levels of conformance: Level A, Level AA, and Level AAA.

This website aims to conform to **WCAG 2.2 Level AA**. It is **partially conformant** with WCAG 2.2 Level AA, which means some content may not yet fully conform to the standard.

## Technical specifications

Accessibility of this website relies on the following technologies:

- HTML
- WAI-ARIA
- CSS
- JavaScript

These technologies are used in combination with modern browsers and assistive technologies to provide an accessible experience.

### Accessibility features

This website includes the following accessibility features:

- A **skip link** to bypass navigation and jump to main content
- A **logical heading hierarchy** for screen reader navigation
- **Landmark regions** (`<header>`, `<nav>`, `<main>`, `<footer>`) for assistive technology navigation
- **Full keyboard navigation** for interactive elements
- **Visible focus indicators** for keyboard users
- **Color contrast** designed to meet WCAG AA requirements
- **Dark and light themes** with user preference support
- **High-contrast and reduced-motion preferences**
- **Responsive design** that adapts to different viewport sizes
- **Text alternatives** for meaningful non-text content
- **Form labels and validation** with clear error identification
- **ARIA attributes** and screen reader labels for interactive components

## Known limitations

- The resume page embeds a PDF hosted by Google Drive. The embedded viewer is provided by Google, so its accessibility depends on Google Drive and the PDF itself.
- Blog articles are fetched from external publishing platforms. Some article content, images, or embeds may be controlled by those platforms.
- Older articles may not have been written with this website's accessibility features in mind.

If you encounter an issue that is not listed here, please [contact me](#feedback).

## Assessment approach

I assess accessibility through:

- Self-evaluation during development
- Automated testing with tools such as axe, WAVE, and Lighthouse
- Keyboard-only navigation testing
- Manual review of focus order, headings, labels, and color contrast
